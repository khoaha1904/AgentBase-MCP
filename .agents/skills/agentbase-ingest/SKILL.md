# Add repository

Prepare one sparse, source-backed proposal for the approved repository; stop
before Publish. An approved Query handoff carries a gap, not source/home authority.
Changed scope needs renewed agreement; cancellation preserves private work.

1. Read [Preflight](references/preflight.md), then `preflight_hub_ingest`.
   Existing canonical identity enters [Refresh](../agentbase-refresh/SKILL.md)
   for the same approved scope, without a repeated command. Ambiguous identity
   stops for clarification. For a new identity, compare bounded repository docs
   with Domain summaries, show evidence/warnings and confirm the preliminary
   Repository default home.
2. Call `discover_repository` on exactly `analysis_source_repository`. A Seed
   not ready means Incomplete. Investigate its five lanes with ordinary source
   read/search; census is sampled evidence. Expanded discovery requires explicit
   confirmation, current seed_id, user_confirmed and reason before Receipt freeze.
3. Qualify candidates from exact paths/spans. Stable identity and independent
   query/contract/ownership/lifecycle/failure value justify promotion; resource
   declarations alone do not. Keep independent frontend/backend/worker runtimes
   separate. Internal modules, queues, storage, alarms and hosts usually remain
   embedded in their runtime parent; a host is never a Server concept. Promote
   Component only with workload evidence. A Flow needs independent reading value,
   not merely one runtime's internal sequence. No fixed concept-count target.
   Label Terraform .tf/.tf.json, Terragrunt orchestration, SAM Serverless types
   and native CloudFormation types truthfully, even within SAM. Cite module or
   inherited Globals source where applicable. IAM is not interaction proof;
   dynamic expressions/transforms/deployed values remain limitations. Prefer
   readily available structured IaC; missing it permits a truthful partial result.
   Do not build or deploy to fill source gaps.
4. Call `get_okf_authoring_schemas` with qualified candidates/observations and
   an Inventory assigning every Seed group exactly one outcome. Materialized
   groups name candidate_ids; repeated IDs may cover distinct evidence for the
   same boundary. Questions use candidate_key/evidence_id from this request.
   Ignored P0 permits only a true duplicate, exact reason duplicate-covered and
   a materialized covered_by_origin_group_id. Never invent MCP-derived IDs,
   sources or revisions. Embedded candidates declare parent_candidate_id and no
   suggested_type; their observations stay self-owned. Standalone candidates may
   share observations. Semantic-only intent names a released suggested_type;
   Interface/Resource additionally needs promotion basis and candidate-owned
   semantic evidence. Structured mapping wins; suggested remains reviewable.
5. Present the Receipt's grouped home plan: default home, exceptional homes and
   separately evidenced Domain participations. Obtain one explicit confirmation.
   Use confirmed_domain for a simple Domain or home_plan, never both. Home is
   placement; participations authorize part-of. A cross-boundary Resource's
   confirmed Domain home also confirms its prepared participation, without
   implemented-in to a foreign owner. Call `prepare_hub_okf` with mode new,
   Receipt ID, source, repositories/<slug> subject and confirmed placement only;
   do not resend mutable guidance/signals/coverage/digest.
6. Follow `agentbase-okf` inside the returned bundle, using exact skeleton paths,
   provenance, navigation and suggested-role limitations. One bounded Hub match
   and continuity.domainConcepts/embedded names help recognize existing resources.
   nameSuggestions are hints: verify both authorized evidence chains, use only
   new links in confirmed scope, retain partial/duplicate names as Questions and
   read fullReport if truncated. Never edit a foreign repo for reverse edges.
   Write compact wiring pages: role, runtime/entrypoint, triggers/interfaces,
   linked IO/stores, flow-changing conditions, retry/DLQ and operations. Aim for
   about 60 body lines; details belong in sources or linked children. Repository
   keeps its own sources and links to promoted children, never their tables.
   Embedded Knowledge and optional Embedded Relations remain parent-owned;
   embedded rows have no identity/file/navigation/canonical edge. New Domains
   summarize only evidenced contributed scope.
7. `validate_okf_changes` receives changed concept Markdown and session_id.
   Preserve observed_revision; each frontmatter relationship needs a resolving
   Markdown body link. Make at most one exact content repair, then
   `finalize_hub_okf_proposal`. Questions/navigation are renderer-owned; never
   author questions/ or activity log.md. A Hub-base replacement uses its new
   session/skeletons without another discovery. Finalize returns proposal_id and
   proposal_digest; call `inspect_hub_okf_proposal` once, review complete hunks,
   semantic impact, Questions, limitations and partial status. Read private files
   or include_content if more context is needed. Report refreshSuggestions and
   the evidence-owning repo for reverse publishes-to/writes-to; do not start it.

Guidance permits at most one stateless INVALID_ARGUMENT input correction with
recovery correct-and-retry-same-tool, separate from the single content repair.
Never automatically retry Prepare/Finalize or unsupported/ambiguous,
internal, authority, integrity, transport or uncertain-state failures. A second
validation failure is Incomplete and needs explicit user retry. Sparse/no-change
is success. No provider CLI, clone, sync, PR rebuild or Publish. No source blocks,
secrets or config dumps in Hub; useful scalars remain observed, not current truth.
