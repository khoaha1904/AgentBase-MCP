# Contract: OKF v0.2 Bundle Proposal and Apply

## Source authority

The base format is Google Open Knowledge Format `v0.2` at the pinned source in
`docs/references/open-knowledge-format.md`. AgentBase concept types, source
descriptors and directive fields are documented producer extensions.

## Shared and local paths

- Current shareable bundle: `<repository>/okf/`.
- Proposed complete bundle:
  `<repository>/.agentbase/proposals/<proposal-id>/bundle/`.
- Apply-only staged and backup sibling directories use unique AgentBase-owned
  names and are recorded in a recovery manifest.

Local proposal/recovery state is ignored by Git. Current `okf/` is not.

## Minimum bundle shape

```text
okf/
  index.md
  log.md                         # optional; consumed but not generated by MVP
  repositories/<repo>.md
  components/<concept>.md
  flows/<concept>.md
  questions/<concept>.md
  guidance/<concept>.md          # human-authored when present
```

The exact number and taxonomy of technical concepts follow evidence. The
accepted fixture requires at least a repository concept, two linked technical
concepts and one open question to prove navigation and uncertainty.

## Conformance

Every non-reserved Markdown file:

- is UTF-8;
- begins with parseable YAML frontmatter;
- has a non-empty free-form `type`;
- uses its normalized bundle-relative path without `.md` as concept ID.

The root index may contain frontmatter with only the supported bundle version:

```yaml
---
okf_version: "0.2"
---
```

Index bodies group normal Markdown links under headings and include descriptions
where available. Log files use newest-first ISO-date headings. Unknown concept
types, extra frontmatter keys, missing optional fields and broken links do not
invalidate base OKF; AgentBase reports broken links as warnings.

## AgentBase producer rules

Every newly generated concept:

- sets `status: draft` explicitly;
- records `generated.by: agentbase/<version>` and an ISO timestamp;
- does not add `verified`;
- records supported provenance in `sources`;
- uses stable source IDs and matching footnotes for important claim attribution;
- encodes source-code resources as normalized
  `repository://<repository-id>/<relative-path>#Lx-Ly` URIs without absolute
  checkout roots;
- links related concepts with standard Markdown links;
- creates an open-question concept only when uncertainty affects an emitted
  concept, relationship or conclusion, and never presents it as verified fact.

Existing generated concepts are continuity context only. Their content cannot
become a `sources` entry without independent repository evidence.

## Human guidance and protected knowledge

Human correction is a normal conformant concept, conventionally under
`guidance/`, with `type: Maintainer Guidance` and `generated.by: human:<id>`.
It links to its subject through Markdown.

AgentBase may modify or delete a concept only when it explicitly has an
`agentbase/` generated actor, `status: draft`, and no human verifier. Every other
concept is protected by default and preserved as exact bytes. Modified mutable
concepts preserve unknown keys by parsed-value equivalence; comments, quoting,
anchors and key order are not promised. New evidence that conflicts with a
protected concept creates a separate draft/open question; it does not edit the
protected file.

An optional defer directive uses the documented `agentbase.directive` extension.
It is AgentBase behavior, not Google OKF behavior.

## Proposal operations

```text
prepare(current bundle, evidence) -> prepared byte-copy workspace + proposal ID
validate(authored proposal, current bundle, evidence) -> generated tree digest + base/producer results
diff(proposal, current bundle) -> tree/content diff
apply(valid proposal, current bundle) -> switched bundle or recovery result
recover(manifest) -> previous or intended next valid bundle
```

`prepare`, `validate` and `diff` never mutate current `okf/`. The host agent may
write only inside the returned proposal `bundle/`. Successful validation changes
proposal state from `prepared` to `generated` and locks its tree digest; later
edits make it stale. Validation reports base OKF conformance separately from
AgentBase producer policy and rejects:

- invalid YAML, empty types or invalid reserved files;
- unsupported/missing root OKF version;
- unsafe/duplicate concept paths;
- malformed required generated/source fields;
- invented verification;
- stale base/evidence digests;
- changed protected concept bytes;
- deletion of a protected/ambiguously owned concept or any implicit rename.

## Bundle apply and recovery

Apply:

1. atomically acquires the repository-local single-writer lock;
2. revalidates current/proposed tree digests and ownership classifications;
3. copies the complete proposal into a same-filesystem staged sibling;
4. verifies staged tree bytes;
5. writes an exact recovery manifest;
6. renames current to the recorded backup when current exists;
7. renames staged next to `okf/`;
8. verifies the active tree digest, finalizes and releases the lock.

If a step fails, recovery uses the exact manifest and owned paths to restore the
previous valid bundle or finish the intended switch. It never searches by a
glob, deletes an unrecognized directory or reports success while the manifest is
unfinished.

Explicitly diffed deletion is allowed only for a mutable AgentBase-generated
draft. Protected/ambiguous deletion, concept rename and semantic merge are
excluded. Deterministic recovery covers declared injected process interruption
checkpoints; the contract does not claim power-loss durability without fsync.

## Required scenarios

1. first bundle from no current `okf/`;
2. multi-concept links and progressive root index;
3. draft/generation/provenance rules;
4. unknown type/key preservation and broken-link warning;
5. no current-bundle mutation during proposal/diff;
6. human guidance byte preservation;
7. persistent defer suppression until explicit reopen;
8. stale AgentBase-draft deletion after visible diff;
9. conflict with human-verified concept becomes separate draft;
10. stale base, base-conformance/producer failure and protected deletion rejection;
11. single-writer conflict and interruption before/between directory renames;
12. deterministic checkpoint recovery and successful explicit apply.
