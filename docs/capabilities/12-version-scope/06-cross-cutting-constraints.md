# 12.06 — Cross-cutting constraints

- **Profile-local after sync:** Code Graph always works locally. Hub authoring,
  review, Accept and Published query can work from the active profile's admitted
  local state after connection/sync; no profile means no Hub/OKF authority.
- **Provenance-first:** knowledge, relations, observations, Questions and human
  guidance retain attributed evidence; Hub is not a second source/code graph.
- **Snapshot-default:** Hub snapshot answers first and source is read only when
  explicitly or operationally required.
- **Cumulative:** omission, age or unavailable source never silently deletes
  accepted knowledge.
- **Human publication gate:** MCP may create/update Hub PRs with its token, but
  never Accepts, merges, approves or publishes automatically.
- **Provider-neutral core:** cloud/product detail is metadata/profile evidence,
  not multiplied schema types.
- **Deterministic trust boundaries:** MCP validates exact bytes, IDs, digests,
  commits, paths and permission scope; AI owns investigation/authoring, not
  lifecycle authority.
- **No speculative machinery:** no daemon, distributed service, generic cloud
  command runner, status database or second knowledge store without measured
  need.
