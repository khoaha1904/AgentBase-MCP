# Expert Delta Review: Corrected OKF v0.2 MVP

- **Captured:** 2026-08-12
- **Status:** Reviewed; blockers resolved in Capability 002 artifacts
- **Trigger:** The original expert review used a single `OKF.md` interpretation
  before the official Open Knowledge Format source was checked.
- **Lenses:** product/UX, technical feasibility and knowledge convergence

## Verdict

The corrected multi-file OKF model does not change AgentBase's product
direction. All three reviewers accepted the graph -> draft -> guidance ->
rebuild vertical slice and agreed that an OKF v0.2 concept bundle is the right
interoperable output.

The delta was material enough to invalidate several storage and lifecycle
assumptions. Implementation was approved only after the active spec, plan,
contracts, data model and tasks incorporated the corrections below.

## Accepted corrections

### Convergence ownership

- A concept is mutable only when it explicitly identifies an `agentbase/`
  generator, has `status: draft`, and has no human verifier.
- Every other concept is protected by default and preserved as raw bytes.
- An explicitly diffed mutable AgentBase draft may be deleted so an incorrect
  first build does not accumulate forever.
- Protected or ambiguously owned content cannot be automatically deleted,
  renamed or merged.

### Defer behavior

- Defer stores a stable directive ID and subject in a `Maintainer Guidance`
  concept.
- It remains active until a maintainer removes or explicitly reopens it.
- The earlier whole-evidence-digest auto-resurface rule was removed because an
  unrelated source edit could reintroduce many ignored questions.
- Evidence-scoped automatic reconsideration remains later work.

### Proposal and host-agent boundary

- Prepare byte-copies the current bundle, records `prepared`, returns an exact
  proposal ID/path and grants the host agent write access only to its `bundle/`
  subtree.
- Successful validation records `generated` and the exact generated tree
  digest. Any later edit makes that validation stale.
- The owner happy path is prepare, inspect the host-agent-presented validated
  diff, then explicitly apply. Validate/diff/recover remain diagnostic commands.

### Provenance and parsing

- Repository source resources use normalized
  `repository://<repository-id>/<relative-path>#Lx-Ly` identifiers and never
  expose absolute checkout roots.
- Base OKF conformance and AgentBase producer-policy validation are separate.
- Protected files bypass YAML serialization. Mutable AgentBase drafts preserve
  unknown parsed values but do not promise YAML comments, anchors, quoting or
  key order.
- The YAML boundary must reject duplicate keys, bound aliases/resources and
  input size, and normalize a bare OKF `verified` mapping as one event.

### Apply and recovery

- State-changing operations use an atomically acquired repository-local
  single-writer lock.
- Recovery guarantees cover declared injected process-interruption checkpoints.
- The MVP does not claim sudden power-loss durability without an explicit fsync
  design.

## Simplifications retained

- `log.md` is consumed when present but not generated by the MVP.
- Only uncertainty affecting emitted knowledge becomes an open-question
  concept.
- The graph/direct-source benchmark is optional evidence and does not block
  release.
- No Hub, cross-repository resolution, AWS/Terraform enrichment, UI, ontology,
  model SDK, custom downloader/native configuration, daemon, rename or semantic
  merge enters Capability 002. Managed provider bootstrap was approved later and
  is recorded separately.

## Approval interpretation

The owner stated that if the corrected OKF model did not materially alter the
product direction, Capability 002 was approved and work should continue. The
review found technical corrections but no product-direction change. The active
artifacts therefore record owner approval after applying these bounded fixes.
