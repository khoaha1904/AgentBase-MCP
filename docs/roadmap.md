# Roadmap

## Current correction: AgentBase-MCP and local AgentBase-Hub

**Status:** Complete through Capabilities 008 and 009 (2026-08-13)

- Make official product identity and ownership explicit.
- Accept reviewed OKF as immediately queryable commits on local Hub `main`.
- Select concrete OKF concept schemas sparsely from Code Graph and related
  evidence.
- Accumulate proposals locally, publish a safe group in one PR, then
  synchronize remaining proposals without loss.
- Qualify canonical `AgentBase-MCP` and `AgentBase-Hub` directories additively;
  external repository/launcher cutover remains separately approved.

Exit: local knowledge works without GitHub publication, multi-repository
pending work can converge safely, and temporary rebuild identity cannot leak
into product defaults or generated subjects.

## Phase 0: Clean foundation

**Status:** Complete (2026-08-11)

- Establish repository routing, product vocabulary and architecture rules.
- Select the runtime and minimal toolchain with evidence.
- Add module ownership, dependency and review-size checks.
- Implement one provider-neutral Code Intelligence contract and deterministic
  fake.

Exit: a new session can implement a focused capability without reading legacy
code, and architecture rules fail automatically when violated.

## Phase 1: Single-repository walking skeleton

**Status:** Complete (Capability 002, 2026-08-12)

- Capture actual Codebase Memory `v0.10.1` one-shot output and mutation behavior
  before shaping the adapter.
- Produce one bounded repository evidence bundle from AgentBase's exact managed
  provider dependency without user paths, global install/config, daemon,
  watcher or `PATH` discovery.
- Use the host coding agent to propose a small conformant OKF `v0.2` bundle of
  linked concepts for one TypeScript repository.
- Show a file-tree/content diff and require explicit recoverable apply to the
  shared `okf/` directory.
- Preserve every non-AgentBase-draft concept and durable defer guidance through
  rebuild, while allowing reviewed deletion of a stale AgentBase draft.
- Optionally benchmark the same task against direct source reading for time,
  context, required-fact coverage and correction count after the loop works.

Exit: one repository completes graph -> draft -> correction/defer -> rebuild,
and the first value evidence is reviewed. No cloud credentials or Hub are
required.

## Phase 2: Local Code Intelligence hardening

**Status:** In progress; scoped-session, freshness-reuse and agent-facing MCP slices complete (2026-08-12)

- Harden managed-provider upgrade/rollback only after walking-skeleton value is
  demonstrated; exact dependency ownership is already settled.
- Use one short-lived provider session per evidence round. Three alternating
  fixture pairs proved normalized parity, clean cleanup and a `4.656x` median
  improvement; retain one-shot as explicit rollback.
- Reuse an exactly accepted unchanged private graph; refresh changed or forced
  source through the provider's existing index operation. Exact add/modify/
  delete evidence is green, while changed index cost remains visible.
- Expose a safe 12-tool Codebase Memory-compatible MCP and concise graph-use
  skill. One connection binds to one explicit repository without global
  installation, source persistence, recursive discovery or a watcher.
- Defer background watching, cache repair/generations and AgentBase-owned
  incremental algorithms until measured product need justifies them.
- Establish latency, memory and context-reduction thresholds from measured
  baselines.
- Evaluate another engine only if the first provider leaves an observed gap.

Exit: Part 1 is independently useful and refreshable for ordinary coding-agent
work without AI-heavy investigation or cloud credentials.

## Phase 3: Observation bridge

**Status:** In progress; explicit observation and schema-catalog slice complete, Terraform/AWS grounding gap recorded (2026-08-14)

- Define stable observation schema, provenance and analyzer identity.
- Select a deliberately narrow first observation family.
- Prove equivalent observations can emerge from non-identical local graphs.
- Prevent engine-private schema from entering durable knowledge.

Exit: a source revision produces reviewable, reproducible observation batches.

## Phase 4: Governed OKF lifecycle

**Status:** In progress; local-first lifecycle and lazy setup slices complete through Capability 009

- Propose OKF changes against existing knowledge.
- Allow incomplete or partially wrong drafts without blocking the build.
- Reuse accepted knowledge and review guidance without treating repeated AI
  prose as new evidence.
- Add review, acceptance, conflict, stale, detach and supersede semantics.
- Add non-destructive ignore and evidence-triggered revisit behavior.
- Prove cumulative re-ingest across independent evidence rounds.
- Make missing observations non-destructive by default.

Exit: repeated investigations improve knowledge while preserving provenance and
human control.

## Phase 5: Enrichment and cross-repository hardening

- Add optional Terraform/Terragrunt or cloud-assisted evidence collectors.
- Add provider permission UX and explicit degradation behavior.
- Harden upgrades, rollback, performance, packaging and multi-repository use.
- Reassess legacy features only when a measured product need remains.
